# AltSnap — portable Windows x64

## Установка и обновление

Скачайте `AltSnap-win64-portable.zip` из успешного запуска GitHub Actions
для актуального коммита `main`. Артефакт GitHub содержит этот ZIP внутри:
распакуйте оба архива в отдельную папку с правом записи.
`AltSnap.exe`, `hooks.dll`, `AltSnap.ini` и `Lang` должны оставаться вместе.
Запускайте `AltSnap.exe`; установщик не требуется. Одновременно работает одна копия.

Перед обновлением откройте **Open ini file** в меню старого AltSnap в трее
(либо средней кнопкой мыши на значке) и запишите путь активного INI. Он может
находиться рядом с EXE либо в `%APPDATA%\AltSnap`. Полностью завершите AltSnap
через **Exit**, сохраните резервную копию INI. Скопируйте весь активный
`AltSnap.ini` в новую папку рядом с EXE, заменив только шаблон из ZIP.
Так сохраняются назначения, исключения, параметры сетки и локальные профили.
Не подменяйте INI файлом `AltSnap.dni` и не смешивайте EXE/DLL разных сборок.
Если настройки ссылаются на пользовательскую тему, отдельно перенесите её файлы.
После запуска проверьте через **Open ini file**, что используется нужная копия.
Старую папку сохраните для возврата: завершите новую копию и запустите старую.

Архив содержит штатный шаблон INI без пользовательских назначений и профилей.
Обновление не назначает сочетания и не включает Linked Grid Resize автоматически.

## Сетка и горячие клавиши

Назначения задаются через **Keyboard → Shortcut for action**. Ниже принятая
пользовательская схема, а не обязательные значения по умолчанию:

| Сочетание | Действие |
| --- | --- |
| Ctrl+Alt+S | AutoTileGrid |
| Ctrl+Alt+Q | AutoTileExpandBoth — расширить по обеим осям |
| Ctrl+Alt+E | AutoTileExpandHorizontal — расширить по горизонтали |
| Ctrl+Alt+F | AutoTileExpandVertical — расширить по вертикали |
| Ctrl+Alt+W | Maximize — максимизация/восстановление |

**AutoTileGrid** размещает 1–8 подходящих окон на мониторе под курсором.
Одно окно занимает рабочую область; два — столбцы; три — левую половину и
две правые ячейки; четыре — сетку 2×2. Для 5/6 используются три столбца,
для 7/8 — четыре, в два ряда. При нечётном числе 5/7 последняя нижняя ячейка
занимает два столбца. При 9 и более подходящих окнах действие отказывается.
Окна другого монитора не перестраиваются.

**AutoTileExpandBoth/Horizontal/Vertical** работают с точной сеткой 2×2 из
четырёх окон на мониторе активного окна и расширяют его область по обеим
осям либо по выбранной оси, согласованно изменяя соседние ячейки.

**Linked Grid Resize** связывает внутренние границы четырёх окон строгой сетки
2×2. Для включения отдельно задайте в `[General]` `LinkedGridResize=1` и
`StickyResize=2`, перезапустите AltSnap. Начните обычный жест resize AltSnap
у внутреннего угла (по умолчанию Alt + правая кнопка мыши). `StickyResize=2`
работает без Shift; варианты 1/3 используют Shift. `FullWin=0` показывает контур,
`FullWin=1` меняет размеры во время движения.

**Maximize/Restore:** зарегистрированный Maximize с Ctrl использует
`ShowWindowAsync`, обходя особую обработку `SC_MAXIMIZE` Проводником Windows 10.
Можно удерживать Ctrl+Alt и отдельно нажимать W для максимизации и восстановления.
Заголовок и кнопки Проводника сохраняются. Мышь и Action Menu работают прежним
способом. Пользователь подтвердил Explorer, Chrome, Total Commander, повторные
и быстрые нажатия, сохранение соседей и работу второго монитора на Windows 10.

## Ограничения

Сетки учитывают ограничения размеров, DPI, исключения и доступность окон.
Неподходящие, зависшие или изменяющиеся окна могут вызвать безопасный отказ;
восстановление после поздней коррекции приложением выполняется по возможности.
Дочерние/owned-окна не допускаются автоматически: существующие совместимые
профили привязаны к пути и версии приложения; после обновления приложения
может понадобиться повторная регистрация через менеджер профилей.
Расширение и Linked Grid Resize требуют именно четырёх окон 2×2.

Максимизация асинхронна. Если чужой UI-поток ещё не применил первый запрос,
два очень быстрых нажатия могут отправить одинаковую команду: строгое чередование
для задержанного/зависшего окна не гарантируется. Между нажатиями HWND и желаемое
состояние не кэшируются; остаётся обычная гонка Win32 при уничтожении окна
непосредственно во время вызова API. Ожидания Ctrl и синтетических клавиш нет.

Сборка и автоматические проверки не заменяют проверку интерфейса приложений.
Сначала сохраните свою INI и проверьте привычные действия, второй монитор и
восстановление окна в прежнюю ячейку. Технические документы и отчёты прежних
тестовых сборок сохранены в репозитории как история.
