# AltSnap: Q/E/W/S, portable x64

Изменения относятся только к `feat/auto-tile-grid`; исходная проверенная база —

## Сохранение рабочей сборки и настроек

Используйте новую отдельную папку. Старую рабочую папку менять не требуется.

1. В старом AltSnap откройте используемый INI через меню значка в трее
   **Open ini file** (либо среднюю кнопку мыши на значке). Зафиксируйте его путь.
   Это может быть `AltSnap.ini` рядом с EXE или
   `%APPDATA%\AltSnap\AltSnap.ini`. Нужен именно активный файл, не `AltSnap.dni`.
2. Полностью завершите старый AltSnap через **Exit**. Сделайте резервную копию INI.
3. Распакуйте новый portable ZIP в отдельную папку. При скачивании артефакта
   GitHub Actions сначала распакуйте оболочку артефакта, затем вложенный ZIP.
4. Скопируйте **весь старый активный `AltSnap.ini`** в новую папку рядом с новым
   `AltSnap.exe`, заменив только новый шаблонный `AltSnap.ini`.
   Это сохраняет горячие клавиши, LinkedGridResize, StickyResize, FullWin,
   списки исключений, раскладки и все записи `[AutoTileOwned1]`…`[AutoTileOwned8]`
   вместе с `Enabled`, SHA-256, путём и параметрами зарегистрированного MobaXterm.
   Переносить отдельные поля или редактировать их вручную не нужно.
5. Если используете собственную тему, скопируйте её файлы из старой `Themes`
   в новую папку. Другие пользовательские ресурсы нужны только если на них
   ссылаются ваши настройки. Оставьте новые `Lang/ru_RU.ini` и остальные файлы
   локализации из архива, чтобы получить новые подписи.
6. Запустите **новые** `AltSnap.exe` и `hooks.dll` из одной папки. Не переносите
   старые EXE/DLL в новую сборку и не смешивайте версии. Дополнительные профили,
   файлы реестра и DLL MobaXterm переносить не требуется.
7. Путь и содержимое самого EXE MobaXterm оставьте прежними. Смена пути, имени
   или версии MobaXterm требует повторной регистрации профиля через существующий
   менеджер: отказ старого отпечатка является ожидаемой защитой.

Старая папка и её настройки остаются резервной рабочей версией. Для возврата
закройте новую копию и запустите старую. Одновременно запускайте только одну.
Новая копия использует скопированный локальный INI; будущие изменения настроек
в ней автоматически в старую папку не переносятся.

## Назначение через GUI

Откройте **Keyboard → Shortcut for action** / **Клавиатура → сочетание для действия**.
Все четыре действия доступны в списке даже без назначенных клавиш.

| Действие | English / Русский | Рекомендуемое сочетание |
|---|---|---|
| AutoTileGrid | Tile windows evenly / Равномерная сетка | Ctrl+Alt+S |
| AutoTileExpandBoth | Grid: expand both / Сетка: шире и выше | Ctrl+Alt+Q |
| AutoTileExpandHorizontal | Grid: expand width / Сетка: шире | Ctrl+Alt+E |
| AutoTileExpandVertical | Grid: expand height / Сетка: выше | Ctrl+Alt+W |

Для каждого действия: выберите его, нажмите **Pick keys**, удерживайте Ctrl+Alt,
нажмите и отпустите нужную букву, затем нажмите **Save**. Если ранее был назначен
Ctrl+Alt+G для AutoTileGrid, выберите AutoTileGrid и сохраните S — это ваше явное
переназначение. Обновление само G не удаляет. Числовые коды вводить не нужно.

Изменение: выберите действие → Pick keys → новая комбинация → Save.
Удаление: выберите действие → Clear keys → Save. Само действие останется в списке.
Сохранение выполняется сразу; перезапуск сохраняет результат.

Дубликат другого действия отклоняется с указанием конфликта. Сначала измените
или удалите старое назначение. Перед записью выполняется пробная RegisterHotKey
с временным освобождением собственных сочетаний. Если Windows/другая программа
занимает комбинацию, старое значение сохраняется, показывается диагностика.
Ошибка записи/проверки INI тоже показывается. Если конфликт появился после
сохранения, ошибка фактической регистрации при загрузке/перезагрузке настроек
выводится отдельно: сочетание явно помечается неработающим, INI не исправляется
автоматически. При дубликатах в вручную изменённом INI действует первое успешно
зарегистрированное назначение; последующие получают сообщение об отказе.

## Поведение сетки

S использует прежний AutoTileGrid: монитор выбирается курсором, доступные 1–4
участника раскладываются равномерно. Для Q→S поставьте курсор на монитор сетки.

Q/E/W выбирают **foreground window и его монитор**, независимо от курсора и
UsePtWindow. Требуется ровно четыре подходящих видимых окна, образующих точную
сетку 2×2 на всю рабочую область. Минимизированное окно не разворачивается.

E двигает общий вертикальный разделитель к допустимому пределу, W — общий
горизонтальный. Q делает оба перемещения одним планом и одной транзакцией.
Для правого/нижнего участника направления автоматически противоположны.
Все ограничения четырёх окон, видимые рамки и нативные размеры участвуют в расчёте.
Соседи остаются видимыми. Повтор на пределе не двигает окна. Неиспользуемая ось
сохраняет текущую пропорцию. Равномерная сетка восстанавливается через S, если
её половинные размеры допустимы для всех участников.

Обычная сетка и сетка после Linked Grid Resize обрабатываются одинаково.
Глобальное состояние сетки не сохраняется: текущая геометрия заново проверяется
при каждом нажатии. Настройки LinkedGridResize, StickyResize и FullWin не меняются.

## Проверка на вашей Windows 10

1. Проверьте сохранённые настройки и включённый профиль MobaXterm в менеджере
   **Blacklist → Owned profiles...**. Не регистрируйте заново неизменённый EXE.
2. Назначьте S/Q/E/W через GUI. Закройте и запустите AltSnap снова: проверьте
   четыре сочетания. Проверьте изменение/удаление одного назначения и восстановите его.
3. Оставьте четыре окна на одном мониторе: MobaXterm и три обычных приложения.
   Закройте их диалоги. Нажмите S, затем по очереди фокусируйте каждый угол.
   Для каждого окна проверьте S→E, S→W, S→Q, повтор Q/E/W на пределе, Q→E→W,
   E→Q, W→Q и Q→S. Перед S курсор должен быть на нужном мониторе.
4. Для Q/E/W поместите курсор над другим окном или другим монитором: расширяться
   должно foreground-окно, в том числе MobaXterm. Проверьте различие E и W.
5. Измените пропорции через Linked Grid Resize, затем повторите Q/E/W. После
   расширения снова перетащите общий внутренний угол. Проверьте ваши FullWin=0/1
   и обычный Sticky Resize по прежней методике, меняя их только на копии настроек.
6. Проверьте минимум соседнего окна, пятое подходящее окно, фокус вне участников,
   нарушенную геометрию, минимизацию участника и модальный диалог MobaXterm.
   В этих небезопасных случаях Q/E/W должны отказаться без перестройки остальных.
   После восстановления четырёх участников S и Q/E/W должны снова работать.
7. Проверьте занятое сочетание: назначьте комбинацию другому действию, затем
   попробуйте такую же для Q. Должно появиться сообщение без изменения назначения.
   По возможности проверьте конфликт с другой программой и отказ регистрации
   после перезапуска. Не отключайте защиту Windows и не повышайте привилегии.

При отказе по ограничениям геометрии окна не «дожимаются» обходными методами.
Для расследования можно использовать существующий opt-in AutoTileTrace;
профильные сведения в сообщения диагностики горячих клавиш не добавляются.

## Автоматизированные проверки и границы доказательств

Проверки включают чистую геометрию, независимый перебор допустимых разделителей,
все углы и оси, разные пропорции, min/max и Win32-переполнение, повторные действия,
Q→S, совместимость с геометрией Linked Resize, адаптеры с подменёнными Win32 API,
профили, минимизацию, модальные состояния, отказы пакета и guarded rollback.
Есть тесты INI/дубликатов/ошибок и ASan/UBSan всего переносимого набора.

CI дополнительно выполняет реальные Windows ANSI/Unicode контракты INI, CryptoAPI,
combobox и занятого RegisterHotKey на Windows Server 2022. Это не проверка
перемещения реальных приложений и не ручной тест страницы настроек Windows 10.
Полный новый пользовательский сценарий Q/E/W с настоящим MobaXterm ещё требует
проверки по списку выше. Предыдущие успешные проверки базы остаются пользовательскими.

Win32 DeferWindowPos не является изолированной транзакцией с чужими процессами.
Снимки и проверки до/после применения отклоняют обнаруженные изменения; существующий
откат возвращает только окна с сохранившимися witnesses. Если приложение сменило
состояние/идентичность или отказало самому откату, принудительно исправлять его
нельзя. Нет обещания атомарности при произвольном поведении чужого приложения.
Старые ограничения DPI-awareness, доступности процесса, owner/modal и профилей
сохранены; повышение привилегий не используется.
